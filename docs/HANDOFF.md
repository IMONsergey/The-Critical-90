# The Critical 90 — передача в разработку

Сайт: https://imonsergey.github.io/The-Critical-90/

## Один источник сборки

`index.html` — разметка страницы и диалогов. `src/styles.css` — токены, компоненты, адаптивы и CSS-анимации. JavaScript разделён на `motion.js`, `interactive.js`, `dialog-focus.js`, `form.js`, `content.js` и `config.js`; точка входа — `main.js`. `public/` содержит только статические ресурсы. Сборка `scripts/build.mjs` формирует `dist/`.

Node.js 22+. Зависимостей у приложения нет. Команды: `npm run build`, затем `npm run dev`. Локальный адрес — `http://localhost:4173/The-Critical-90/`. После изменения исходников повторить сборку.

## Макет

Источник — актуальные Desktop, Адаптивы, Хедер и UI-kit во вкладке KASPER WEB, файл Figma `lQfOm1SOxe7rAnLQdeCfpA`; основной фрейм `704:3137`. Иллюстрации экспортированы из последней версии, включая четыре разных состояния cyber shifts. Тексты страницы не заменяются текстами старых прототипов.

Button и DownloadAction намеренно разделены. Первая — контентная кнопка, вторая — компактная pill-кнопка шапки с круглым значком скачивания. Адаптивность реализована общей сеткой и CSS, без отдельных копий компонентов под каждый экран.

## Типографика и изображения

Kaspersky Sans Display подключён через официальный CORS-enabled `cdn.kaspersky.com`, начертания 300/400/500/600. Шрифтовые файлы не входят в репозиторий. Для финального размещения команда бренда может указать собственный лицензированный источник в `public/brand-fonts.css`.

Все иллюстрации находятся в `public/assets/`; временных Figma URL в runtime нет. Векторные логотипы, тематические иконки и декоративные числа сохранены как SVG. Растровая графика оптимизирована в WebP.

## Интерактив

Нативный скролл, одноразовое раскрытие секций, мягкая реакция hero на мышь, локальные световые реакции карточек и прогресс чтения. Cyber shifts: четыре изображения, клавиатура, свайп, управляемое автопереключение. Автоматическая смена приостанавливается вне экрана, в скрытой вкладке, при фокусе, наведении и открытых диалогах. Ручной выбор останавливает её до нажатия Play.

Бургер, обзор отчёта и детали 30/60/90 используют нативные dialog с Escape, удержанием фокуса и возвратом на кнопку открытия. `prefers-reduced-motion` отключает декоративное движение и автоматическую смену слайдов.

## Требуется для боевых интеграций

В `src/config.js` заполнить `reportUrl`, `previewUrl` и `formEndpoint`. Сейчас адреса не предоставлены: кнопки открывают обзор с явной пометкой об отсутствии PDF, форма проверяет ввод, но не передаёт и не сохраняет данные и не имитирует успешную отправку.

API формы должен принимать JSON по HTTPS и разрешать запросы с домена сайта. Серверу нужны собственная валидация, защита от спама и ограничения частоты. Подписка на новости необязательна, согласие на обработку обязательно. Дополнительные языки подключать только с утверждёнными текстами.

## Проверка и публикация

Единственный workflow `.github/workflows/pages.yml` проверяет JavaScript, собирает сайт и запускает Chromium / Playwright на 320, 375, 480, 640, 768, 960, 1024, 1200, 1366, 1440 и 1920 px. Проверяются загрузка изображений и шрифтов, переполнения, навигация и фокус, слайдер, диалоги, валидация формы, reduced motion и читаемость без JavaScript. Скриншоты и JSON-отчёт сохраняются в artifact `browser-review`.

После успешных проверок изменения `main` автоматически публикуются в GitHub Pages. Workflow дополнительно проверяет настоящий commit в публичных build.json и meta build-revision, рендеринг без авторизации на 320/1440 px и работу слайдера. Зелёный CI дополняется отдельным визуальным сравнением шести размеров с Figma.
